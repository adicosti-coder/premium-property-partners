# Admin components rules
- WhatsApp admin work lives in the single `hub-whatsapp` screen (`WhatsappHub.tsx`): queue/attention/report rules come only from `supabase/functions/_shared/waHubRules.ts` (tested in `src/lib/waHub.test.ts`), quick actions (retry/unblock, test send, resolve) go only through the admin-only `wa-hub-actions` function, which logs each one in `admin_audit_log`; legacy WhatsApp pages stay reachable as hub tools and old URLs — keeps one classification of 131042/131026/duplicates and no secret or test number in the browser.
- Collected-listing triage (`triere-anunturi`, `ScrapedListingsTriage.tsx`) groups cross-portal duplicates only via `src/lib/crossPortalDedup.ts` (cross-portal only, every variant must match the group's primary, implausible prices/sizes ignored) and filters/orders via `src/lib/scrapedListingsTriage.ts`, both tested; sending goes through `andrei-bulk-queue` and is blocked client-side by `triageBlockReason` when no phone was extracted — avoids merging distinct homes and queuing listings that need a manual phone reveal.
- Triage „Indisponibil / Renunță” goes only through admin RPCs `admin_dismiss_prospect` / `admin_restore_prospect`: the listing becomes inactive + `expired`, leaves the first-message queue, its pending WhatsApp/owner-outreach/call items are cancelled, the previous state is kept in `dismissed_prev` for undo and both actions are audited; the list hides dismissed listings before duplicate grouping via `triagePool` — nothing is deleted, and a dismissed primary never hides its live variants.
- Triage „Confirmă privat” goes only through admin RPCs `admin_confirm_prospect_private` / `admin_undo_confirm_prospect_private` (audited, full prior state in `private_confirm_prev`); `private_confirmed_at` wins first in `classify_seller_type`, so confirming removes the number from `agency_blocklist`, clears any manual agency mark, reactivates a listing deactivated only by the blocklist (no auto send/call), re-checks same-number siblings (they stay agency on other signals) and stops the multi-listing rule from re-adding the number; agency-flagged rows need the separate override dialog, text-keyword agencies are refused; undo restores the listing, siblings and blocklist row exactly; button choice from `privateConfirmMode` — the admin's explicit owner decision must not be undone by number-based automation.
- Triage „Agenție” goes only through admin RPCs `admin_mark_prospect_agency` / `admin_undo_mark_prospect_agency` (audited, prior state and cancelled queue items in `agency_mark_prev`); a valid RO phone (mobile 07… or real county landline) propagates the mark to same-number listings (`agency_mark_root`) except private-confirmed ones, whose presence also keeps the number off `agency_blocklist`; undo from any group member restores the whole group exactly (`app.restore_triage_state` bypasses reclassification) and removes only the blocklist row it added; sent history is kept and undo never triggers a first message; button choice from `agencyMarkMode` — prevents junk numbers (dates) blocking unrelated owners and partial undos.
- Search/category/aggregator/article pages saved as listings are recognised only by `isSearchPageUrl` (`src/lib/listingUrl.ts`, byte-identical mirror `_shared/listingUrl.ts`, parity-tested) and its SQL mirror `public.is_generic_search_listing`; Triage drops them before grouping (`triagePool`) and per row (`matchesBase`) — change all three together so the list, counters, ingestion and stored data agree.
- Triage phone add/correction uses `ProspectPhoneEditor` → admin-only `admin_update_prospect_phone`: changes only the current listing, validates RO landlines/mobiles, cancels unsent items for the old number and re-evaluates eligibility without touching sent history or sending automatically — prevents wrong-number outreach while keeping manual correction available.
- General listing portals (publi24, OLX, Storia, Facebook…) are recognised only by SQL `is_classified_portal_domain` and can never be blocked as whole domains (`agency_blocklist` trigger drops them; classify/enforce/auto-blacklist skip them); inactive non-dismissed listings are reactivated only by admin RPCs (`admin_reactivate_prospect`, `admin_confirm_prospect_private`, mobile phone correction) under `app.admin_reactivate` + `app.skip_auto_outreach`, with no auto send — one portal domain must not silence every private owner on it.
- Manual „Confirmă privat” lifts `lead_score` to at least 75 via DB trigger `zz_private_confirmed_min_score` (any row with `private_confirmed_at`), mirrored client-side by `asConfirmedPrivate` — the admin's owner check outranks the photo penalty, so the send button is never falsely blocked; undo restores the prior score.
- Triage disables „Trimite către Andrei” for numbers still inside the 30-day first-message window using `buildOutreachCooldownMap`/`outreachCooldownFor` (same status filter as `outreach-dispatch`) and shows the dated hint from `outreachCooldownHint`; the server check stays authoritative — avoids confusing `recent_outreach_30d` errors without changing the rule.
- Every triage card shows when the listing was collected through `collectionDisplay` (`src/lib/scrapedListingsTriage.ts`, tested): relative text (`scraped_at` → `created_at` → `last_seen_at`) with the full Europe/Bucharest date and time in the `title`/`aria-label` and revealed inline on tap — one source for both formats keeps hover and touch identical.
