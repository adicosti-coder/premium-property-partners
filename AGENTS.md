# Project Architecture Rules

- LanguageProvider allows explicit English selection; SEOHead shares the language robots policy and the provider supplies an English fallback tag — prevents partial translations from becoming indexable while preserving Romanian route restrictions.

- Visitor-memory AI summaries require a verified user and session ownership before metered work; automation completion RPC is service-role-only — prevents unauthorized credit consumption and job manipulation.
- Restaurant-guide JSON-LD escapes HTML tag openers and lead-magnet diagnostics record only fixed messages/status codes — prevents stored script injection and personal data in logs.

- Social extraction reads active properties and published blog articles locally, without external scraping — avoids credit consumption for data already stored.
- Database triggers block new draft/scheduled copies of published social content and clean sibling drafts on publication; source identity ignores format fragments and matches exact normalized titles — prevents repeated content across feed and Stories, including separate property imports.
- Admin sale offers use existing RLS; owner decisions go through a locked ownership-checking RPC that changes only status and enforces the saved minimum — prevents cross-owner edits.
- Social AI editor supports all post types and statuses with editorial illustrations only and explicit gallery selection; editing published posts never republishes them automatically — prevents hidden controls, invented photographs and accidental reposts.

- Social growth reads only published feed previews through a bounded public RPC; campaign redirects resolve admin-created allowlisted destinations with social UTM tags — prevents draft exposure and open redirects.
- Social WhatsApp P.S. modifies only existing free-text confirmations/follow-ups, never Meta-approved templates or consent/STOP messages — preserves consent and send counts.

- Keep the homepage hero LCP image sets strictly separated by mobile/desktop media queries so high-DPR phones never fetch desktop assets.
- Start the decorative desktop hero video only after genuine user interaction so the responsive image remains the stable LCP candidate.
- Auto-consented listings view joins prospect/contact data with normalized WhatsApp names and exports filtered rows via shared tested helpers — avoids invented owner data.
- Automatic property publishing prepares a cropped stored cover before activation and derives bedrooms from original source descriptions via a shared deterministic helper — prevents raw portal footers and living rooms counted as bedrooms.
- The Advisor injects mandatory geography from stored property GPS or explicitly approximate district references and versions its cache when geography rules change — prevents stale or invented compass positioning.
- Property offers and Advisor investment cards share `getPropertyInvestmentMetrics`, keeping unrounded annual income until display — prevents inconsistent yields and rental multipliers.
- Property maps and POI travel estimates use `propertyGeo` resolved GPS with explicit district fallback profiles — prevents imported Iosefin listings inheriting city-center coordinates or fixed travel times.
- Chunk-load recovery allows at most one automatic refresh per URL per minute and never refreshes offline or deletes unrelated caches — prevents reload loops and preserves cached resources.
- Keep toast hosts mounted at startup, isolate route errors with a location-reset boundary, and delay nonblocking route-loading feedback briefly — preserves early notifications and prerendered content without blank navigation.
- Voice campaign controls use an in-page confirmation, serialize updates, and announce success only after persistence; call-log refreshes retain existing rows — avoids blocked browser confirmations, misleading feedback, and polling flicker.

- Subdirectories have their own `AGENTS.md`; read it before changing files there.
- Firecrawl is a secondary fallback only: every call goes through `_shared/firecrawlBudget.ts` (`firecrawlFetch`) with a DB-backed monthly credit cap; Apify and the internal direct scraper run first — exhausted credits return a soft 402 so imports never block.
- New private-owner prospects are sent to Make.com outreach only via trigger `trg_fire_make_outreach` → `outreach-dispatch`; Make.com reports back through `outreach-status` (shared-secret header) into `prospect_listings.outreach_status` — one outreach channel avoids double WhatsApp sends. Every Make.com outreach payload carries `phone` as full international digits without `+` (Romanian mobile `07…` → `407…`), produced by the single helper `toOutreachPhone` in `_shared/waPhone.ts` — one phone shape keeps the Make scenario mapping valid.
- Agent integrations: tools live in `src/lib/mcp/` (one `defineTool` per file, OAuth via caller-scoped client + RLS); the `mcp` function is SDK-generated — never hand-edit, republish after changes.
- Internal team reminders are scheduled as rows in `public.admin_reminders` and delivered once by `functions/admin-reminder-check` (hourly pg_cron `admin-reminder-check-hourly`, status flips to `sent` before the next tick) — one delivery path prevents duplicate or ad-hoc pings.
- Admin DB health page `/admin/stare-baza` reads only the admin-gated `admin_db_health_snapshot()` RPC (pg_stat counters, no platform metrics) — keeps instance stats behind the admin role.
- `automation-orchestrator` is called by pg_cron with `x-cron-secret` and gated by `requireInternalOrAdmin`; due-ness is computed via croner `nextRun` from max(last_run_at, now−10min) — admin-only auth and croner `previousRun` silently stopped every automation for a month.
- Social Engine cron sends at most one feed post and one Story per hour (09–21 Bucharest), tracked through `social_engine_logs.trigger` (`cron_job` / `cron_story`) — prevents bursts and duplicate sends.
- Property `size` is auto-synced from `usable_area` by trigger `trg_sync_property_size` — all cards read `size`, so usable area shows uniformly.
- Andrei prompt auto-optimization (`optimize-agent-prompt`) only stores one `pending` row in `agent_prompts_history`; the active `voice_agent_scripts` prompt changes solely via admin RPC `review_agent_prompt`, which snapshots the old version and refuses stale proposals — no unreviewed prompt reaches live calls.
- Owner-form phone fields validate through `roMobileField` in `src/lib/phoneField.ts`, which strips typed/autofilled separators (spaces, dashes, dots, parentheses) before the Romanian-mobile check and returns the normalized number — placeholders show "07XX XXX XXX", so spaced input must never block a lead.
- Owner consent follow-up runs daily (Mon–Sat) via `wa-consent-reminder` action `auto`: it reconciles `outreach_pending` rows that already have a WhatsApp outbound, sends the single reminder, and tags private owners silent 48h after it with `consent-no-reply` for one Andrei call in `voice-batch-campaign-tick` — Make callbacks are unreliable and manual-only reminders never ran.
- Owner dashboard panels stay mounted while the selected property changes, so any editable field in `src/components/owner/` must derive its visible value from the current `propertyId` plus an edit tagged with that id — never from a `useEffect` that only writes when stored data exists — otherwise one property's value carries into another and gets saved there.
- Prospect pre-checks live in DB triggers: `developer_agency_signal` keywords set `seller_type='de_verificat'` ("Needs Review") before any `privat` classification, and `fill_prospect_surface_price_sqm` derives size/€-per-m² from text when missing; scraper owner scans run only from the single 4x/day cron with per-platform 402 incidents in `scraper_health_incidents` — keeps Andrei off developer listings and avoids overlapping scans.
- Manual „Trimite către Andrei” sends WhatsApp first via `andrei-bulk-queue` → `outreach-dispatch` (single Make channel); voice is only a fallback queued once by `_shared/voiceFallback.ts` when WhatsApp dispatch fails or `outreach-status` reports `failed`, then `voice-batch-campaign-tick` dials one at a time in call hours — keeps calls off owners reachable on WhatsApp and prevents duplicates.
- The WhatsApp assistant (`wa-andrei-reply`) books only property evaluations as `pending` rows in `chatbot_appointments`, validated by `_shared/waAssistantBooking.ts`, and hands off by setting `awaiting_human` plus one alert to the owner via the WhatsApp alert webhook — the owner confirms every slot, so the AI never promises a fixed appointment.
- Lite-model translations and agency classifications pass deterministic checks in `_shared/liteOutputChecks.ts`; suspicious results are not applied and go to `automation_approvals` as `review_ai_output` — cheap models never silently publish wrong text or blacklist owners.

- Management calculators use the shared commercial-policy helper with channel fees and utilities explicit and cleaning separate — prevents gross/net commission drift.
- Additional calculator leads share `CalculatorLeadForm`, the `calculator_unificat*` source prefix and direct Meta/CRM delivery, bypassing legacy alerts and Make WhatsApp — prevents duplicate notifications while preserving each new calculation.
- Calculator submissions use a payload-bound stable submission UUID; channel sends atomically claim per-lead state and only definitive failures permit channel-specific admin retry, while capability-scoped polling and signed Meta/Resend receipts confirm delivery — prevents duplicate saves, cross-channel resends and false receipt promises.
- Homepage calculator anchors stay outside lazy boundaries; both hash aliases and CTAs force loading and wait for the tool's step-independent readiness marker before scrolling — prevents jumps to placeholders and broken navigation after step 1.
- Viewing requests persist through the protected lead endpoint before opening WhatsApp or emitting Lead; failures produce neither chat navigation nor conversion — prevents false conversions.
- Prerendered HTML ships one static Romanian canonical that the global route Helmet emitter replaces on mount; singular complex routes have a client fallback to plural — prevents duplicate canonicals while server redirects remain hosting-owned.
- Social publication claims use `posting`, not `posted`; only confirmed external IDs finalize publication, failures return to draft with errors and partial delivery preserves successful platforms — prevents false published states and duplicate retries.
- English on public pages falls back to `PhraseTranslator` (exact-phrase map in `public/i18n/en-phrases.json`, lazy-loaded, skips admin/owner portal/blog articles); new hardcoded Romanian copy needs a map entry or a dictionary key — avoids rewriting every page while translations are partial.
- PhraseTranslator restores its text and attribute mutations on cleanup only while they still match its translated values — prevents mixed-language round trips without overwriting newer React content.
- Audited public routes use shared publicRouteSeo metadata in SEOHead and prerender; Romanian-only SEO overrides never replace English metadata — prevents delayed stale or mixed-language head tags.
- Commercial review configuration remains disconnected from public copy until administrator approval; managed, accommodation and promoted inventory are separate metrics — prevents resolving disputed figures by assumption.
- Owner lead forms emit one conversion after persistence; confirmation-page visits emit none, and GA4 automatic page views are disabled in favor of the existing SPA emitter — prevents duplicate or unverified conversions.
- Language switching updates the existing language query through the router while preserving other parameters, hash and state — prevents reload from undoing the visitor's choice.
