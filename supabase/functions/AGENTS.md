# Edge Function Rules
- Andrei Training Lab simulates text-only Andrei vs Gemini-persona conversations in `voice-agent-training-lab` and applies admin-selected fixes as active playbook lessons — improves the prompt without placing real calls.
- Andrei's prompt appends objection points derived only from the listing's real price, zone and size/rooms via the shared policy helper; Training Lab can simulate real campaign listings by ID without calling owners — keeps objections factual and type-specific.
- SellerScan classifies `prospect_listings.seller_type` (privat/agentie/de_verificat) in a DB trigger from the agency blocklist, phone reuse across distinct listings and agency score; the batch campaign calls only `privat` — keeps agencies and unconfirmed sellers out of Andrei's automatic calls.
- Andrei's post-call WhatsApp follow-up is enqueued by `voice-agent-status` only after an explicit DA, via the approved Meta template in `_shared/andreiFollowup.ts`, skipping 131026/DNC/already-sent numbers — no unsolicited messages.
- Andrei books calendar slots via `_shared/andreiCalendar.ts`: slots are fetched only on firm intent, stored on the transcript entry and booked only from an explicit `[REZERVA:n]` marker after re-checking free/busy — prevents invented times and double bookings.
- Training Lab `auto_loop` runs in the background (daily cron), saves runs to `voice_call_analyses` (source `training_lab_auto`) and keeps at most 5 active playbook lessons — bounds AI cost and prompt size.
# Edge function rules

- Social Engine publishes server-side via `process-scheduled-posts`, using an atomic `posting` claim; confirmed IDs finalize `posted`, total failures and interrupted claims return to draft with errors, partial delivery preserves confirmed platforms, and Make acceptance alone is not delivery — avoids false publication and duplicate retries.
- AI image/text features run through shared handlers (_shared/aiClient, aiVision, aiText) exposed as `ai-vision` and `ai-text-generation`; legacy function URLs stay as thin entry points and text results are cached by sha256 in `ai_text_cache` — one auth/error/model path without breaking callers, crons or webhooks.
- Listing/contact pages ship a static #route-shell heading (prerender plugin) removed on first React H1 (max 3s) so real-user FCP/LCP don't wait for the JS bundle.
- WhatsApp first-contact templates always use the Meta-approved resolver (v6 → v5 → v3), never an environment override; outbound stops for DNC/STOP or any prior inbound interaction.
- Client qualification reuses history/zone and separates owner handover; AI reads latest ordered turns and discards stale replies — avoids repeated questions.
- Owner-consent queue messages resolve their dedicated template against Meta's approved Romanian body at send time; use the existing intro resolver until approval so inspection templates never reach owners.
- WhatsApp sends normalize phones via `_shared/waPhone.ts` (all format variants in DB lookups) and reserve the number in `request_idempotency` before calling Meta; no automatic resend after timeouts — prevents duplicate messages from parallel or delayed runs.
- Admin „Publică acum” calls `publish-consented-listing` (consent check, per-prospect lock, retries on 5xx, audit) instead of the worker directly — prevents double or silently failed publications.
- Lead inserts in edge functions never chain `.single()` after insert — the dedupe trigger returns 0 rows on merge and `.single()` makes the API roll the merge back.
- /analiza-anunt extracts listing data via `public-listing-analysis` and scores it deterministically in `listing-market-score` (scraper comparables, last 180 days) — keeps price/negotiation numbers reproducible instead of AI-invented.
- Voice Command Center cards load details/WhatsApp history on demand by prospect ID + phone variants; phone edits update both phone fields with concurrency checks, past conversations untouched — keeps records intact.
- Voice simulator gets the first visible prospect by ID via the admin-only context proxy; phone is separate from listing identity, stale responses discarded — preserves property context.
- Append the shared concise conversation policy after voice scripts and learned lessons, with sales examples only on sales calls; reuse it in drills — keeps runtime brevity and factuality rules consistent even with custom scripts.
- All automatic WhatsApp replies pass the shared guard and pre-send reservation — stops refusal and duplicate sends.
- Consent auto-publish only queues a social draft; `social.autopost_drain` posts one per interval via `_shared/metaSocial.ts`, claims first, logs per platform, falls back to draft on Meta errors; amenities only from fixed AI visual-tag vocabulary — avoids rate limits, duplicates, invented features.
- Blog autopilot saves one factual DRAFT per run; admin publishes; 402/403 pauses it.
- WhatsApp audits use real ordered turns; approved lessons stay separate from voice, with compare-and-restore rollback — prevents wrong-channel training.
- Calculator leads send via approved Meta templates using stored figures and visitor capability or internal auth; per-channel atomic claims replace legacy reservations for new requests, definitive failures allow admin retry and uncertain outcomes stay locked; signed callbacks reconcile early receipts — prevents open sending, duplicate retries and false delivery states.
- Feed photo posts (manual and scheduled) publish directly via `_shared/metaSocial.ts` and count as posted only with a Meta post ID logged in `social_autopost_logs`; Make stays only for Stories/Reels — Make answered "success" while Meta silently dropped posts.
- Owner first-contact buttons live in `_shared/waOwnerOutreachTemplate.ts` (Meta template sent by Make; payload carries template name, zone and the short `https://realtrust.ro/e/<short_code>` link from `_shared/estimateShortLink.ts`, resolved publicly only through RPC `get_estimate_link`); `outreach-status` stores the echoed template in `wa_publish_consents.request_template`, and button/affirmative consent is valid only with that template (`ownerOutreachConsentCheck`); every WhatsApp owner consent goes through `_shared/ownerConsentApproval.ts` and stays `pending_approval` until the admin 1/2 decision unless already admin-approved; hotel-calc button and owner questions are logged in `make_lead_events` and alert both admin numbers while Andrei keeps replying — consent proof, manual review and human hand-off follow one path.
- SEO re-audits run sequentially via `src/lib/seoReaudit.ts` (timeouts recovered from latest `seo_audits` row); legacy aliases audit at canonical path (`_shared/seoAuditTarget.ts`); active `seo_overrides` are scored — avoids false failures.
- `outreach-dispatch` is the only owner first-contact send path: 09:00–19:30 Europe/Bucharest (else `queued` + `outreach_scheduled_at`, drained by orchestrator job `wa.owner_outreach_queue_drain`), one send per phone per 30 days (`_shared/ownerOutreachPolicy.ts` + `request_idempotency`), `unsubscribed` numbers blocked; replies in the buttons flow go through `ownerOutreachReplySignals` — one place enforces timing, anti-spam and opt-out.
- Owner 30-day re-contact runs only in `wa-owner-recontact` (orchestrator job `wa.owner_recontact`): one per listing (`outreach_recontact_at` claimed atomically), queued as `wa_outbound_queue` source `owner_recontact` with its own Meta template, which the worker keeps and sends only 09:00–19:30 — no second unsolicited follow-up path.
- Monthly market alerts go only through `process-monthly-alerts` (admin/internal auth): subscriber selection and payload live in `_shared/monthlyMarketAlert.ts` (tested), one POST per contact to `MAKE_MONTHLY_ALERT_WEBHOOK`, claimed atomically in `market_alert_deliveries` (one per lead and month; only `failed` may be retried; old values = last values sent); hotel-regime index columns are generated from the calculator engine by `src/lib/marketIndexHotelReference.ts` and parity-tested against the seed — prevents duplicate alerts, invented history and hotel figures diverging from the calculator.
- Core Web Vitals monitoring: the live site sends each visitor's LCP/CLS/INP/FCP/TTFB with device class and build release to the validated public RPC `record_web_vital`; `web-vitals-regression-check` (pg_cron every 6h, admin on demand) applies `_shared/webVitalsRegression.ts` (tested, also used by `/admin/viteza-site`) and alerts once per metric/device/day by team e-mail + WhatsApp alert webhook — one rule set decides both the dashboard badge and the alert.
- GSC URL Inspection results go through `_shared/gscIndexingClassification.ts` (tested) in `seo-indexing-alerts`, `seo-alert-monitor` and the admin SEO panels: "Alternate page with proper canonical tag", NEUTRAL with an accepted declared canonical elsewhere, and "Page with redirect" verified clean by `_shared/redirectTrace.ts` (HTTP 3xx or meta-refresh, ≤2 hops, no loop, 2xx indexable self-canonical target) are expected — never counted, e-mailed or alerted; unchecked or faulty redirects stay issues. Filter URLs and consolidated slugs redirect or canonicalize on purpose.
- Admin Connection Health (database, Meta WhatsApp, Make) is computed only by `connection-health` (admin/internal) with green/yellow/red rules in `_shared/connectionHealthRules.ts` (tested, shared with the UI); results are cached 10 min as `conn_*` rows in `external_keys_health`, and an unreachable endpoint is shown as backend down — secrets never leave the function and one cache serves the pill and the card.
- Guest guide secrets are filtered by `_shared/guestGuideAccess.ts` (Bucharest dates: PIN/Wi-Fi during stay, instructions from the day before, none after check-out; admins all); visitor memory returns only `publicVisitorMemory`; property views keep referrer origin + device class (trigger `normalize_property_view`) — keeps access codes and browsing data private.
- Guest review staff alerts are dispatched only by the `submit_property_review` RPC (pg_net + `x-cron-secret`); `send-review-notification` accepts internal calls only — a browser can never choose which review is notified.
- The public chatbot reduces the visitor-reported page to a plain path and one fixed page kind via `_shared/chatPageContext.ts` (tested); only fixed guidance text reaches the system prompt — visitors cannot inject or combine instruction blocks.
- Repeat lead submissions merged by trigger `leads_dedupe_upsert` only fill empty fields and log the submitted values in `activity_history`; `submit-lead` returns no lead id or report token for a merged lead, and chat CRM stages move only for leads the chat created — a public caller cannot prove they own a stored contact.
- Owner outreach eligibility lives only in `_shared/ownerOutreachEligibility.ts` (mirrored by SQL `prospect_is_agency`): agencies → `blocked_agency` with no outreach or automatic reply, automatic first contact/cold queue/re-contact only for `seller_type='privat'` with score above the shared threshold; `trg_fire_make_outreach` fires on insert, first automatic score rise (fresh listings) and manual private confirmation — one rule for dispatch, queue, webhook, bulk and admin selection.
